# Git 提交信息生成规则

## 总体要求

- 所有提交信息必须使用**中文**编写
- 遵循 Conventional Commits 规范，使用中文类型前缀
- 提交信息应简洁明了、准确描述本次变更内容
- 禁止使用模糊表述（如"修改"、"更新"、"调整"），需说明具体改了什么

## 提交类型（中文前缀）

| 类型前缀 | 含义 | 适用场景 |
|----------|------|----------|
| `feat:` | 新功能 | 新增功能模块、新增接口、新增页面 |
| `fix:` | 修复缺陷 | 修复 Bug、修复报错、修复逻辑错误 |
| `docs:` | 文档变更 | 修改 README、注释、文档文件 |
| `style:` | 代码格式 | 空格、缩进、分号等格式调整（不影响逻辑） |
| `refactor:` | 重构 | 代码重构，不改变功能 |
| `perf:` | 性能优化 | 提升性能、减少资源消耗 |
| `test:` | 测试相关 | 新增或修改测试用例 |
| `chore:` | 构建/工具 | 依赖更新、配置文件、构建脚本变更 |
| `ci:` | CI/CD | 持续集成配置变更 |
| `build:` | 构建系统 | 构建工具、打包配置变更 |

## 格式规范

### 单行提交（小改动）

```
<类型>: <简要描述>
```

示例：
```
feat: 新增设备点检记录导出功能
fix: 修复员工列表分页查询返回空数据的问题
docs: 更新部署说明中的 Nginx 配置示例
```

### 多行提交（大改动）

```
<类型>: <简要描述>

- <变更点1>
- <变更点2>
- <变更点3>

<可选：补充说明或影响范围>
```

示例：
```
feat: 新增设备全生命周期管理模块

- 新增设备采购申请与审批流程
- 新增设备安装调试记录功能
- 新增设备点检计划自动生成
- 新增设备润滑保养提醒

影响范围：设备管理相关页面及接口
```

## 生成原则

1. **先读 diff 再生成**：根据实际代码变更内容生成，不要凭空猜测
2. **动词开头**：描述使用动词开头，如"新增"、"修复"、"优化"、"删除"、"调整"
3. **具体明确**：说明具体改了什么，而非笼统地说"修改代码"
4. **按重要性排序**：多行提交中，重要变更排在前面
5. **标注影响范围**：涉及多模块变更时，在末尾标注影响范围
6. **不写废话**：不要写"本次提交主要做了以下修改"之类的套话

## 禁止事项

- 禁止使用英文提交信息
- 禁止使用无意义的提交信息（如"111"、"test"、"update"、"修改"）
- 禁止使用过长的单行提交（超过 50 字应拆分为多行）
- 禁止在提交信息中包含敏感信息（密码、密钥、内部地址）
- 禁止使用感叹号结尾（如"完成功能！"）

## 参考示例

```
# 新增功能
feat: 新增配件库存预警功能

# 修复问题
fix: 修复设备购买审批流程中状态未正确更新的问题

# 文档更新
docs: 补充接口文档中售后管理模块的 API 说明

# 代码重构
refactor: 将设备查询逻辑抽取为独立 Service 方法

# 性能优化
perf: 优化设备列表查询，增加数据库索引

# 依赖更新
chore: 升级 Element UI 至 2.15.14 版本

# 测试相关
test: 新增设备管理模块的单元测试用例

# 配置变更
chore: 修改 application.yml 中的数据库连接池参数
```
